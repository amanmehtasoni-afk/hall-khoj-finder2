Chapter 02 • Strategic Overview
1. Executive Summary & Industry Opportunity

Hall Khoj Finder (hallkhoj.com) is an enterprise-grade, mobile-optimized multi-vendor event marketplace engineered to organize the fragmented ₹4,00,000+ Crore ($50 Billion) Indian wedding and event venues ecosystem. In India, planning weddings, receptions, and corporate galas has historically required grueling physical visits, multiple rounds of opaque bargaining, and reliance on commission-hungry brokers.

Hall Khoj solves these pain points by offering an end-to-end digital discovery, 3D spatial tour, live availability verification, and transparent advance token reservation platform. Recognizing ground realities in Indian Tier-1, Tier-2, and Tier-3 cities, the system completely removes email registration barriers for ordinary consumers—operating purely on high-trust 10-digit Indian Mobile Numbers (+91) with instant SMS OTP verification.

📱 Consumer Empowerment

Zero-friction mobile OTP access, transparent per-plate and rental pricing, real-time date calendar, and 3D virtual floor walkthroughs.

🛡️ Vendor Growth Engine

Dedicated business management suite, multi-image hall galleries, date-blockers to eliminate double-booking, and verified partner credibility.

⚙️ Superadmin Control

Comprehensive dashboard with real-time Gross Booking Volume (GBV), commission settlement engine, KYC document verification, and fraud prevention.

Chapter 03 • Market Analysis
2. Problem Statement & The Indian Market Gap
PROBLEM 01
Opaque Pricing & Hidden Broker Margins

Families routinely pay 10% to 20% in inflated rates due to unauthorized local middlemen and agents who gatekeep contact details.

PROBLEM 02
Email Verification Drop-off Rate

Over 85% of Indian customers use mobile phones without active desktop email client access. Forcing email verification causes over 65% drop-off.

PROBLEM 03
Misleading Photos & Spatial Ambiguity

Filtered 2D photos fail to convey pillar obstructions, stage elevation, mandap arrangement, or parking capacity.

PROBLEM 04
Catastrophic Double-Bookings

Venues relying on paper diaries frequently double-book during high-demand "Auspicious Muhurat" dates, resulting in massive client panic.

✓ The Hall Khoj Solution Framework
  • Frictionless Mobile (+91) OTP Login: Instant 6-digit SMS OTP onboarding in under 10 seconds.
  • Interactive 3D WebGL Virtual Tour: Three.js powered spatial inspection of halls, stage, and dining zones.
  • Real-Time Date Blocker: One-click calendar locking for offline events to eliminate double bookings.
  • Shield Verified Partner Badge: Owner email & GST/Aadhaar document verification to establish trust.
Chapter 04 • Architecture Design
3. High-Level System Architecture & Component Flow
1. Presentation Layer (Mobile PWA)

Pure HTML5, Vanilla CSS3, Modern ES6+, Three.js WebGL Engine, Leaflet Maps. Sub-600ms first paint on 4G networks.

2. API Gateway (Express 5.x)

RESTful endpoints, rate limiting, CORS whitelisting, Multer multipart form handling, JWT authentication middleware.

3. Domain Business Services

Auth Service, Venue & Gallery Engine, Booking & Token Calculator, Admin Analytics, Gemini AI Natural Language Matcher.

4. Supabase PostgreSQL Persistence

Supabase PostgreSQL cloud store + Resilient local atomic JSON data layer to prevent any service interruptions.

End-to-End Booking Lifecycle Workflow
  1. Customer selects city, category (e.g. Banquet Hall), and plate budget on mobile app.
  2. Backend queries database with category and location filters; returns sorted results.
  3. Customer explores 3D WebGL Virtual Tour and browses high-res multi-image photo gallery.
  4. Customer checks date availability; calendar shows green (Available) and red (Blocked) dates.
  5. Customer enters mobile number; receives instant 6-digit SMS OTP via Twilio/Fast2SMS.
  6. Advance token payment initialized via Razorpay/Cashfree; webhook signature mathematically validated.
  7. PDFKit compiles official booking invoice receipt; venue owner receives instant SMS booking alert.

⚡ Why Vanilla JS & CSS instead of Heavy React/Next.js?

For the Indian mobile demographic, bundle size is the #1 driver of user drop-off. Heavy React/Next bundles often exceed 400KB-1.5MB of JS, triggering 3-5 second delays on 3G/4G networks. Hall Khoj uses pure native DOM manipulation with modular Vanilla ES6+ and modern CSS variables, delivering sub-600ms load times and 98+ Google Lighthouse mobile performance scores.

Chapter 06 • Data Models
5. Complete Database Design, Schemas & Collections
1. users (Customer Model)
{ _id: ObjectId, fullName: String, phone: String (Unique, Indexed), role: "customer" | "vendor" | "admin", savedHalls: [ObjectId], createdAt: Date, updatedAt: Date }
2. vendors (Owner Profile)
{ _id: ObjectId, businessName: String, businessCategory: String (1 of 11), phone: String (Unique), email: String, isEmailVerified: Boolean, badgeStatus: "Pending" | "Verified Partner", panNumber: String, gstNumber: String }
3. halls (Venue & Availability)
{ _id: ObjectId, vendorId: ObjectId, name: String, category: String, address: { city, state, pincode, coordinates: [lng, lat] }, capacity: { minGuests, maxGuests }, pricing: { vegPlate, nonVegPlate, rentalDay }, primaryImage: String, galleryImages: [String], blockedDates: ["2026-11-15", "2026-11-16"] }
4. bookings (Reservation Slip)
{ _id: ObjectId, bookingCode: "HK-2026-9812", hallId: ObjectId, userId: ObjectId, eventDate: "2026-12-04", totalAmount: Number, advancePaid: Number, paymentStatus: "Advance_Paid", paymentGateway: { orderId, paymentId } }
Database Indexing & Query Optimization
  • 2dsphere Geo-Index: On location.coordinates for instantaneous distance filtering ($near queries).
  • Compound Index: On { city: 1, category: 1, 'pricing.vegPlate': 1 } for sub-15ms search results.
  • Unique Sparse Indexes: On phone and email to eliminate duplicate accounts.
Chapter 07 • Integrations Matrix
6. Third-Party APIs, Credentials & Operational Flow
1. SMS OTP (Twilio / Fast2SMS)
Keys: SMS_API_KEY, TWILIO_ACCOUNT_SID

Issues 6-digit cryptographic OTPs to Indian mobile numbers (+91) via DLT-approved transactional routes for instant customer verification.

2. Payment Gateway (Razorpay / Cashfree)
Keys: RAZORPAY_KEY_ID, KEY_SECRET

Facilitates UPI (GPay, PhonePe, Paytm), Net Banking, and Cards for advance tokens. Validates HMAC-SHA256 signatures to eliminate tampering.

3. Cloud Media CDN (Cloudinary / S3)
Keys: CLOUDINARY_API_KEY, API_SECRET

Receives cover photos and multi-image galleries. Performs automated WebP compression, watermarking, and responsive CDN delivery.

4. Generative AI (Google Gemini NLP)
Keys: GEMINI_API_KEY / AI_STUDIO_KEY

Parses natural language queries (e.g., "Find me a lawn in Ranchi for 800 guests under ₹1,200 plate") into structured database filters.

5. Maps & Geocoding (Leaflet / OSM)
Keys: MAPTILER_API_KEY

Provides vector map tiles, venue pins, distance calculation from customer GPS location, and reverse geocoding.

6. Transactional Mailer (Nodemailer)
Keys: SMTP_HOST, SMTP_USER, SMTP_PASS

Exclusively utilized for Venue Owners to verify business email addresses, issue monthly settlement summaries, and deliver official invoices.

Chapter 10 • Security & UX
9. Security Hardening & Mobile-First Performance
🔒 Stateless JWT Auth

Tokens signed with HS256 encryption enforcing strict Role-Based Access Control (RBAC) across customer, vendor, and admin scopes.

🛡️ Bcrypt Salted Hashing

10 rounds of salted Blowfish hashing for all administrative credentials. Passwords are never stored or logged in plain text.

💳 HMAC-SHA256 Webhooks

Banking webhook callbacks are mathematically verified using secret cryptographic hashes to eliminate payment falsification.

⚡ Anti-SMS Flooding Shield

Strict IP and phone rate limits (max 3 OTPs per 10 minutes) prevent automated bot abuse and SMS balance exhaustion.

Chapter 11 • API Contracts
10. Complete REST API Endpoints Specification
Method Endpoint Route Auth Level Description & Contract
POST /api/auth/send-otp Public Dispatches 6-digit SMS OTP to given 10-digit mobile number (+91).
POST /api/auth/verify-otp Public Validates OTP and issues customer stateless JWT authentication token.
POST /api/auth/vendor/register Public Registers venue owner with chosen business category & credentials.
POST /api/auth/vendor/login Public Authenticates vendor via email/phone and returns JWT token.
GET /api/auth/vendor/verify-email Token Link Validates token link and grants "Shield Verified Partner Badge".
GET /api/halls Public Lists halls filtered by city, category, capacity & budget parameters.
GET /api/halls/:id Public Returns detailed venue specs, amenities, 3D model, and reviews.
POST /api/halls Vendor Auth Creates new venue profile with pricing, slots, and cover thumbnail.
PUT /api/halls/:id Vendor Auth Updates venue details, amenities, capacities, and plate prices.
POST /api/halls/:id/gallery Vendor Auth Multer multi-upload endpoint appending up to 10 photos to gallery.
POST /api/halls/:id/block-date Vendor Auth Locks offline event date on calendar to prevent double-booking.
POST /api/bookings/create User Auth Initializes booking reservation and creates Razorpay order.
POST /api/bookings/verify-payment User Auth Validates payment signature and generates official booking PDF.
GET /api/admin/metrics Admin Auth Returns real-time GBV, active listings, vendor counts, and alerts.
